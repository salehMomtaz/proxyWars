# راهنمای جامع راه‌اندازی SSH Certificate Authority (CA) در ویندوز ۱۱ و اوبونتو ۲۴.۰۴
این مستند راهنمای گام‌به‌گام راه‌اندازی احراز هویت مبتنی بر **گواهینامه (Certificate)** با استفاده از یک **CA شخصی** برای ورود بدون رمز عبور (Passwordless) به چندین سرور لینوکس از طریق کلاینت **PuTTY 0.83** در ویندوز ۱۱ است.

## ۱. مزایای روش CA نسبت به کلید سنتی
* **مدیریت متمرکز:** نیازی به کپی کردن کلیدهای عمومی کاربران در فایل `authorized_keys` تک‌تک سرورها نیست.
* **کنترل زمان اعتبار:** می‌توان برای گواهینامه‌ها تاریخ انقضا تعیین کرد (مثلاً اعتبار فقط برای ۵۲ هفته).
* **تعریف دسترسی‌ها:** مشخص کردن اینکه این گواهینامه فقط برای ورود به کاربر خاصی (مانند `root`) مجاز است.

## بخش اول: ساخت کلید کاربر در ویندوز

در سیستم‌عامل ویندوز، کلید جفت جفت (اصلی) خود را تولید می‌کنیم:

1. برنامه **PuTTYgen** (نسخه 0.83 یا بالاتر) را اجرا کنید.
2. نوع کلید را در پایین صفحه روی **Ed25519** قرار دهید.
3. روی دکمه **Generate** کلیک کرده و ماوس را حرکت دهید تا کلید ساخته شود.
4. بخش‌های **Key passphrase** و **Confirm passphrase** را خالی بگذارید (برای ورود کاملاً بدون پسورد).
5. روی **Save private key** کلیک کرده و کلید خصوصی را با نام `my_shared_key.ppk` ذخیره کنید.
6. متن داخل کادر بالا (کلید عمومی) را کپی کرده و در یک فایل متنی با نام `my_shared_key.pub` ذخیره کنید.

## بخش دوم: ایجاد SSH CA و امضای کلید در لینوکس

برای تولید کلید مرجع (CA) و امضا کردن کلید کلاینت، مراحل زیر را در یک ماشین لینوکسی امن انجام دهید:

### ۱. ساخت کلیدهای CA
دستور زیر را اجرا کنید تا زوج کلید CA ساخته شود (توصیه می‌شود برای امنیت بیشتر، روی کلید CA یک پسورد قوی بگذارید):

```
ssh-keygen -t ed25519 -f ~/.ssh/ssh_ca_key -C "My Personal SSH CA"
```

این دستور دو فایل تولید می‌کند:
* `~/.ssh/ssh_ca_key` (کلید خصوصی CA - **بسیار حساس و محرمانه**)
* `~/.ssh/ssh_ca_key.pub` (کلید عمومی CA - **باید روی سرورها کپی شود**)

### ۲. انتقال کلید عمومی کاربر به لینوکس برای امضا
فایل `my_shared_key.pub` (که در بخش اول در ویندوز ساختید) را به سرور لینوکس منتقل کنید.

### ۳. امضای کلید و صدور گواهینامه (Certificate)
با دستور زیر، کلید عمومی خود را توسط کلید خصوصی CA برای مدت ۵۲ هفته و فقط برای کاربر `root` امضا کنید:
```
ssh-keygen -s ~/.ssh/ssh_ca_key -I "user_identity" -n root -V +52w my_shared_key.pub
```
* **خروجی:** فایلی به نام `my_shared_key-cert.pub` در کنار کلید عمومی ایجاد می‌شود که همان **گواهینامه** شماست. این فایل را دانلود کرده و به ویندوز منتقل کنید.

## بخش سوم: ادغام گواهینامه در PuTTY

برای اینکه کلاینت PuTTY از گواهینامه استفاده کند، باید آن را به فایل `.ppk` معرفی کنیم:

1. برنامه **PuTTYgen** را در ویندوز باز کنید.
2. از منوی **File > Load private key**، فایل `my_shared_key.ppk` را لود کنید.
3. از منوی بالا به مسیر **Key > Add certificate to key** بروید.
4. فایل گواهینامه دانلود شده یعنی `my_shared_key-cert.pub` را انتخاب کنید.
5. روی **Save private key** کلیک کنید تا کلید خصوصی جدید حاوی گواهینامه ذخیره شود.

## بخش چهارم: پیکربندی سرورها برای اعتماد به CA

اکنون باید سرورهای مقصد را طوری تنظیم کنیم که به هر گواهینامه‌ای که توسط CA ما امضا شده، اعتماد کنند.

### ۱. قرار دادن کلید عمومی CA روی سرور
محتوای فایل `ssh_ca_key.pub` را در مسیر زیر در سرور ذخیره کنید:
```
sudo nano /etc/ssh/trusted_ca_keys.pub
```
### ۲. تنظیم کانفیگ SSH Daemon
فایل پیکربندی SSH را باز کنید:
```
sudo nano /etc/ssh/sshd_config
```
خط زیر را به انتهای فایل اضافه کنید تا سرور کلید مرجع را بشناسد:

```
TrustedUserCAKeys /etc/ssh/trusted_ca_keys.pub
```
> ⚠️ **نکته بسیار مهم:** دقت کنید که هیچ‌گونه تنظیمات تداخلی یا مسدودکننده‌ای (مانند خطوط اضافه مربوط به نرم‌افزارهای حذف شده مثل `slipgate-ssh` یا بلاک‌های `Match Group`) در این فایل باقی نمانده باشد.

### ۳. اعمال تغییرات
ابتدا صحت ساختار فایل کانفیگ را بسنجید:

```
sudo sshd -t
```
اگر خطایی وجود نداشت، سرویس SSH را ری‌استارت کنید تا تنظیمات اعمال شوند:

### در اوبونتو ۲۴.۰۴ نام سرویس ssh است (بدون d)
```
sudo systemctl restart ssh
```

## نکات طلایی عیب‌یابی (Troubleshooting)

اگر پس از انجام مراحل بالا با خطای `Server refused our key` مواجه شدید، مراحل زیر را به ترتیب برای عیب‌یابی انجام دهید:

### ۱. فعال‌سازی حالت دیباگ زنده در سرور
برای دیدن دلیل دقیق رد شدن کلید توسط سرور، سطح لاگ را موقتاً ارتقا دهید:
1. فایل `/etc/ssh/sshd_config` را باز کرده و خط زیر را فعال/اصلاح کنید:
   ```text
   LogLevel DEBUG
   ```
2. سرویس را ری‌استارت کنید: `sudo systemctl restart ssh`
3. لاگ‌ها را به صورت زنده مشاهده کنید:
   ```bash
   sudo journalctl -u ssh -f
   ```

### ۲. بررسی خطاهای رایج در لاگ
* **تداخل نرم‌افزارهای جانبی:** اگر خطایی مانند `user root does not match group list` دیدید، یعنی فیلترهای گروه‌بندی قدیمی در فایل `sshd_config` مانع ورود کاربر `root` می‌شوند. خطوط اضافه را پاک کنید.
* **ری‌استارت نشدن درست سرویس:** دقت کنید که در اوبونتو دستور `sudo systemctl restart sshd` کار نمی‌کند و باید از `ssh` استفاده کنید. تا زمانی که سرویس به درستی ری‌استارت نشود، گواهینامه کار نخواهد کرد.
* **ارسال کلید خام به جای گواهینامه:** در لاگ دیباگ دقت کنید که عبارت `publickey test pkalg ssh-ed25519-cert-v01@openssh.com` دیده شود. اگر عبارت فاقد کلمه `-cert` بود، یعنی PuTTY همچنان در حال ارسال کلید خام معمولی است و گواهینامه به درستی روی فایل `.ppk` لود نشده است.
